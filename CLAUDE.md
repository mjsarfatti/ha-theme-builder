# HA Theme Builder — working rules

A self-contained web app for building Home Assistant themes: a sidebar of knobs, a
live preview of tokens and HA cards, and paste-ready YAML output.

**Read `docs/PLAN.md` first.** Don't change it without a PM decision.

## Verify versions — never assume them

Your training data is out of date. This project has been bitten twice.

Before pinning a version or saying what's "current", check it:
`curl -sS https://registry.npmjs.org/<pkg>/latest` (bypasses the proxy), Context7,
or the web. Check the **major**, not just the patch. For a package days or weeks
old, read the release notes for ecosystem gaps first. Prefer current; if you stay
behind, say why in the PR. Same for GitHub Actions versions, CLI flags and
framework APIs.

## Toolchain

- **pnpm only.** Version pinned in `package.json` via `packageManager`.
- Scripts: `dev`, `build`, `preview`, `lint`, `typecheck`, `test`.
- `lint`, `typecheck`, `test`, `build` must all pass. Never hand back a red PR.

## Working rules

- One work package = one branch off latest `main` = one draft PR. Conventional
  Commits.
- **Never merge a PR.** Open it, get CI green, report it. Only the repo owner
  merges, and only when they say so explicitly.
- End every GitHub comment or PR body with `---` then
  `_Generated by [Claude Code](https://claude.ai/code)_`
- Stay inside your brief. Flag judgement calls in the PR body, especially where you
  overruled a reference document.

## Boundaries

- **`.references/` is read-only.** `ha_theme_analysis.md` (how HA theming works),
  `template.css` (the knob spec: `KNOB` = user control, `DERIVED` = computed,
  `NOTE:` = product requirement), `colors/` (preset data), `claude-design/`
  (preview blueprint).
- **HA's own source wins.** Both derived docs have confirmed errors — the analysis
  doc's §7.5 says the contrast threshold is 4.5 where HA uses 6
  (`apply_themes_on_element.ts:91`); `template.css` aliases `text-primary-color` to
  body text when HA defines it as text *on* primary (`color.globals.ts:10`). When
  they conflict or look wrong, read
  `https://raw.githubusercontent.com/home-assistant/frontend/dev/<path>` — usually
  `src/resources/theme/color/color.globals.ts` (public variables) or
  `src/common/dom/apply_themes_on_element.ts` (engine + derivation maths). Cite file
  and line.
- **`src/engine/` is pure TypeScript.** No React, no DOM. API is frozen — read
  `src/engine/README.md`; changing it costs a PM decision.
- **Theme variables never go on `:root`** — scoped preview containers only, so
  builder styling can't leak into the preview.
- **shadcn/ui comes from the CLI.** Base UI primitives, `base-nova` style — the
  bare `shadcn init --template vite` defaults. Install with `pnpm dlx
  shadcn@latest add <name>`; never hand-write or hand-port a component. Editing
  `src/components/ui/` afterwards is fine — say so in the PR, and use
  `add <name> --diff` to merge upstream changes later.
  Read the `shadcn` skill before writing UI; it covers customisation, composition
  (Base UI uses `render`, not Radix's `asChild`) and the CLI.

## Decided — don't relitigate

- v1 knobs are exactly the `KNOB` annotations in `template.css`.
- Light and dark previews show side by side, always. No mode toggle.
- Ramps and palettes are presets from `.references/colors/`. No custom controls.
- **Never the browser-native colour input.** Custom picker, can pick from the
  active ramp and palette.
- HA ships only Roboto; other fonts need an `extra_module_url` snippet with the
  exported YAML.

## Network

Egress allowlist, varies by session — check, don't assume.
`registry.npmjs.org`, `raw.githubusercontent.com` and `ui.shadcn.com` are
reachable; `unpkg.com` and `cdn.jsdelivr.net` have been blocked. A 403 on
CONNECT is a policy denial: report the host, never route around it or disable TLS.
Diagnose with `curl -sS "$HTTPS_PROXY/__agentproxy/status"`.

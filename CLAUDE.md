# HA Theme Builder — working rules

A self-contained web app for building Home Assistant themes: a sidebar of knobs, a
live preview of tokens and HA cards, and paste-ready YAML output.

**Read `docs/PLAN.md` first** — scope, decisions, architecture, milestones. Do not
change it without a PM decision.

## Never assume tool or library versions — verify them

Your training data is out of date, by more than you expect. This project has
already been bitten twice.

Before adding a dependency, pinning a version, or saying what "current" is:

- Check it: `curl -sS https://registry.npmjs.org/<pkg>/latest` (the npm registry
  bypasses the egress proxy), or Context7, or the web.
- Check the **major**, not just the patch. A wrong major means reading docs for
  software that no longer works the way you think.
- For a package only days or weeks old, check the release notes for known
  ecosystem gaps before adopting it. Recency is not a reason; a verified upgrade is.
- Prefer current versions. If you deliberately stay behind, say why in the PR body.

Same applies to GitHub Actions versions, CLI flags, and framework APIs. If you are
about to write a version or a flag from memory, stop and check.

## Toolchain

- **pnpm only.** Never npm or yarn. Version pinned in `package.json` via
  `packageManager`.
- Scripts: `dev`, `build`, `preview`, `lint`, `typecheck`, `test`.
- `lint`, `typecheck`, `test` and `build` must all pass before you hand back a PR.
  Never hand back a red PR.

## Working rules

- One work package = one branch = one draft PR into `main`. Branch off the latest
  `main`, commit in logical chunks (Conventional Commits), push with
  `git push -u origin <branch>`.
- End every GitHub comment or PR body with, as the final lines:
  `---` then `_Generated by [Claude Code](https://claude.ai/code)_`
- Stay inside your brief. Flag judgement calls in the PR body rather than burying
  them — especially anywhere you had to overrule a reference document.

## Boundaries

- **`.references/` is read-only.** Source material: `ha_theme_analysis.md` (how HA's
  theme system works), `template.css` (the knob spec — `KNOB` is a user control,
  `DERIVED` is computed, and the `NOTE:` comments are product requirements), the
  colour-ramp and palette pages (preset data), and the Claude design artifact
  (preview blueprint). Read it constantly; never modify it.
- **Home Assistant's own source is the final authority.** `ha_theme_analysis.md` and
  `template.css` are *derived* documents and each has a confirmed error: the
  analysis doc's §7.5 gives the contrast threshold as 4.5 where HA uses 6
  (`apply_themes_on_element.ts:91`), and `template.css` aliases `text-primary-color`
  to the body text colour when HA defines it as the text drawn *on* the primary
  colour (`color.globals.ts:10`). When the references contradict each other,
  contradict themselves, or look wrong, read the real thing —
  `https://raw.githubusercontent.com/home-assistant/frontend/dev/<path>` is
  reachable. Most answers are in `src/resources/theme/color/color.globals.ts` (the
  public theme variables) and `src/common/dom/apply_themes_on_element.ts` (the
  YAML→CSS engine and the derivation maths). Cite file and line when a decision
  rests on one.
- **`src/engine/` is pure TypeScript.** No React, no DOM. Seeds in, token maps and
  YAML out. Its public API is frozen — read `src/engine/README.md` and build against
  it; changing it costs a PM decision.
- **Generated HA theme variables never go on `:root`.** They go on scoped preview
  containers, so the builder's own shadcn/Tailwind styling cannot leak into the
  preview or vice versa.

## Product constraints already decided

- The v1 knob set is exactly the `KNOB` annotations in `template.css`. No additions.
- Light and dark previews are shown **at the same time**, side by side. No mode
  toggle.
- Ramps and palettes are **presets only** in v1, taken verbatim from
  `.references/colors/`. No custom colour-space controls.
- **Never use the browser-native colour input.** Seed colours use a custom picker
  that can also pick from the active ramp and palette.
- HA ships only Roboto, so any other font needs an `extra_module_url` loading
  snippet shipped alongside the exported YAML.

## Network

Sessions run behind an egress proxy with an allowlist. `registry.npmjs.org` and
`raw.githubusercontent.com` are reachable. `ui.shadcn.com`, `unpkg.com` and
`cdn.jsdelivr.net` have been blocked, though the allowlist can change between
sessions — check rather than assume. A 403 on CONNECT is an organisation policy
denial: report the blocked host, never route around it or disable TLS verification.
Diagnose with `curl -sS "$HTTPS_PROXY/__agentproxy/status"`.

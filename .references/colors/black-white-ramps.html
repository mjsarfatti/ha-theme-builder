Methodology — deriving a HA-compatible ramp from any tinted neutral set (click to expand)

Goal: given an arbitrary set of "neutral" colors from some other system — any number of steps, any spacing, possibly slightly tinted, possibly missing true black and/or white — produce a 13-step ramp at HA's exact positions (00, 05, 10, 20, 30, 40, 50, 60, 70, 80, 90, 95, 100) that keeps HA's own lightness progression but carries the input's tint character.

Why this works regardless of step count or spacing: the whole method is keyed on lightness, not on position index. A ramp with 6 steps and a ramp with 40 uneven steps both reduce to the same thing — a scattered set of (L, C, H) points in OKLCH space — so the input's own labeling scheme never has to line up with HA's.

1. Convert everything to OKLCH. HA's 13 real hex values, and every color in the input set, both via the standard sRGB → linear → OKLab → OKLCH pipeline.

2. Sort the input by L, not by its original order. Discard whatever position/index scheme the input uses. What matters from here on is only each color's own lightness — this is what makes the method indifferent to how many steps the input has or how they're spaced.

3. Build C(L) and H(L) curves from the input. Treat the input's (L, C) pairs as samples of a chroma-vs-lightness function, and its (L, H) pairs as samples of a hue-vs-lightness function. If hue barely moves across the set (the common case for a "tinted gray" — a few degrees of drift), collapse it to a single average H and skip the hue curve. If hue drifts meaningfully, keep it as a function of L like chroma, interpolated the same way.

4. Anchor the ends. If the input already contains true black (L≈0) and white (L≈100), use its own C there — nearly always 0, but not assumed. If the input doesn't reach one or both ends, pin C=0 at the missing end(s) rather than extrapolating a trend off the last real sample: chroma curves from small hand-picked hex sets tend to swing unpredictably under extrapolation, and forcing true neutrality at full black/white matches how virtually every real neutral system behaves at its extremes anyway.

5. Smooth C(L) before sampling from it. Small, hand-tuned neutral ramps are usually built by eyeballing or rounding hex values one step at a time, not from a single continuous formula — so the raw C(L) curve usually has some rounding noise: a step that dips lower or spikes higher than its neighbors for no perceptual reason. A light moving average (e.g. 3-point) over the L-sorted chroma values removes this without flattening the input's real, larger-scale shape (a genuine dip-in-the-middle or fade-at-the-ends survives smoothing; single-step noise doesn't). Re-pin the endpoints to C=0 after smoothing, since a moving average will otherwise leak a little chroma into them from their neighbors.

6. Sample onto HA's 13 target lightnesses. For each of HA's own 13 real L values, look up C (and H, if it varies) from the smoothed input curves via linear interpolation — or, for any HA lightness that falls outside the input's L range entirely, via the pinned endpoint value rather than extrapolating past data the input never provided.

7. Recombine and convert back. Take (HA's own L, sampled C, sampled H) per step, convert OKLCH → OKLab → linear sRGB → sRGB, clamp to [0,1] per channel, and output as hex. HA's L is always used verbatim and never touched — only chroma and hue are borrowed from the input.

Caveat: this whole approach assumes the input set is trying to be a neutral (or near-neutral) ramp in the first place — i.e. its hue stays roughly consistent across steps. If the input mixes genuinely different hues at different lightnesses (not just noise, but an intentional warm-to-cool shift or similar), a single averaged hue will wash that out; use the per-L hue curve from step 3 instead of collapsing to a scalar.
